Cómo crear elementos para los Xpacios isométricos

Especificación para diseñar props, mobiliario y superficies a medida que encajen, pixel-perfect, en el motor isométrico de Admira XP (el Digital Twin de XpaceOS).

Documento de referencia · derivado del motor real (game.html) · proyección 80×28

01 Proyección 02 Huella 03 Anclaje 04 Iluminación 05 Render 06 Pantallas 07 Entregables 08 Vía nativa

En una frase: cada elemento vive sobre una rejilla de rombos de 80×28 px; las líneas de suelo van a ±19,3° y las alturas suben verticales en píxeles puros. Si se dibuja con otro ángulo, no encaja.

01Proyección — qué define "nuestro" isométrico

No es el isométrico clásico 2:1. El tile base es 80 × 28 px:

  • Ratio del rombo: tileW:tileH = 80:28 ≈ 2,86:1
  • Ángulo de las líneas de suelo: atan(14/40) ≈ 19,3° sobre la horizontal — un dimétrico "aplanado", más bajo que el 26,57° estándar.
  • Eje vertical (altura): recto hacia arriba, en píxeles puros. Un objeto de altura H sube H px verticales, sin inclinarse.

Un tile de suelo es un rombo de 80 ancho × 28 alto. Vértices respecto al de arriba: derecha (+40,+14), abajo (0,+28), izquierda (−40,+14).

Regla de oro para diseño: verticales = verticales en pantalla; horizontales siguen ±19,3°. Cualquier sprite con otro ángulo NO encaja.

02Huella (footprint) — todo va sobre rejilla

Cada elemento ocupa N×M tiles de suelo. La huella se mide en tiles; la altura, en píxeles.

  • Ancho = nº de tiles en X · Fondo = nº de tiles en Y · Altura = px
  • 1 tile = 80×28 px. Ej.: un mostrador de 1×2 tiles = 40 px de frente × 80 px de fondo en planta.

03Anclaje (pivot) — para que no "flote"

  • El anclaje es la esquina origen del tile de la huella (vértice superior del rombo base, el punto rojo del diagrama). El objeto se apoya ahí, crece hacia arriba (altura) y hacia derecha/abajo (huella).
  • Entregar cada PNG con su anchor marcado, o mejor en un JSON acompañante.
{
  "id": "expositor-tabaco",
  "footprint": [1, 2],     // ancho × fondo en tiles
  "heightPx": 90,
  "anchor": [40, 118],     // px del PNG que toca el suelo en la esquina origen
  "screenRect": null,      // o [x,y,w,h] si lleva pantalla
  "palette": { "top":"#a88860", "left":"#6a5030", "right":"#8b6b45" }
}

05Dos modos de render

Entregar compatible con ambos. Si entregáis PNG, hacedlo en estilo 16-bit (es el de feria).

  • flat: color plano por cara (look limpio/retro).
  • 16-bit: gradiente diagonal en la cara superior, gradiente vertical en laterales, sheen blanco al 12–20% en aristas superiores, líneas de arista negras de 0,6 px.
  • Neón (opcional): glow de color en las dos aristas superiores, para acentos/marca.
  • Sombra: elipse de contacto en el suelo bajo la huella (la pinta el motor) — dejad hueco transparente, no la queméis.

06Superficies de pantalla (signage)

Si el elemento lleva pantalla, su contenido es una zona 16:9, base 160×90 px, que el motor rellena con vídeo/imagen en vivo.

Importante: dejad la pantalla como hueco/marco transparente. No queméis contenido dentro — el twin lo inyecta en tiempo real.

07Entregables técnicos

  • PNG transparentes, preferible @2x (tile lógico 160×56) + versión @1x. Alpha real, sin sombra quemada.
  • Un archivo por elemento (+ hoja de sprites si hay estados: on/off, día/noche…).
  • JSON por elemento: footprint, heightPx, anchor, screenRect, palette.
  • Paleta limitada y plana (encaja con el look canvas); evitar texturas fotográficas.

08Alternativa nativa (opcional, integración más barata)

El motor dibuja por código, no por imágenes. La primitiva es:

drawIsoBlock(col, row, ancho, fondo, alturaPx, topCol, leftCol, rightCol, neonCol)
//            ↑ posición en rejilla   ↑ huella en tiles  ↑ px   ↑ 3 caras + neón opc.

Si pixeria entrega el elemento descompuesto en cajas (lista de prismas: huella + altura + 3 colores), lo integramos sin imágenes y pesa 0 KB. Ideal para mobiliario sencillo (mostrador, expositor, peana).
